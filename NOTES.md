# mod-playerbots implementation notes (stages/phases, core bot support)

Moved verbatim from CLAUDE.md on 2026-10-10 (dated session notes; may be stale, verify before relying on them).

- Bot support in core: `WorldSession(..., isBot=true)` has no socket, is NOT in World's session map (updated by `PlayerbotMgr`), `SendPacket` hands packets to `SetBotPacketHandler`, `LoginBotPlayer(guid)` logs a same-account character in, `InitializeSession(callback)`; `PlayerScript::OnUpdate(player, diff)` fires at end of `Player::Update`. `WorldSession::SetBotFrozen` skips `Unit::Update` and `Map::VisitNearbyCellsOf` for lonely bots (AI skip alone still woke every outdoor grid). Frozen bots `LoadGrid` + snap Z from the **current Z** (not `MAX_HEIGHT` — that is the mountain roof over Ironforge/tunnels). Party bots skip snap and keep the master's Z. `.appear` onto a sky-snapped bot drops you through the world. Bots must complete the teleport handshakes themselves (`HandleMoveTeleportAck`, `HandleSuspendTokenResponse`, `HandleMoveWorldportAck`).
- Docker `playerbots.conf`: UpdateInterval 1000, LoginBatch 1, OnlyWithPlayers 1, BotActiveAlone 0, Zone 0 (only radius 150 yards; AC's 10% leftover-active and Zone=1 keep continents hot).
- mod-playerbots layout (`modules/mod-playerbots/src`): `RandomBotMgr` (accounts, login batches, homes), `GearFactory`, `RemoteControl` (TCP, off by default), `PlayerbotAI` + `Strategies/` (relevance-sorted actions: Revive 100 > Teleport 90 > Heal 80 > Consume 75 > Attack 60 > Loot 50 > Pvp 30 > Quest 20 > Idle 10), `Strategies/QuestTravel` (kill quests only), `ActivityMgr` (bots only FILL queues of online humans: LFG roles, BG teams, arena opposing group; answers LFG proposals from `SetBotPacketHandler` with delay via world-thread queue). A human group leader counts as the bot's temporary master (follow), so random bots in a player group follow. Bots call the same `WorldSession::Handle*` functions a client would (`HandleBattlemasterJoinOpcode`, `HandleBattleFieldPortOpcode`, `sLFGMgr->JoinLfg/UpdateProposal/UpdateRoleCheck`). A separate playerbots DB is not possible from a module (only the 4 built-in DB pools exist). Docker runs `/trinity/bin/worldserver` from `trinity-server/bin` (copy `build/bin/RelWithDebInfo/bin/worldserver` there; `Text file busy` until the container is stopped). Random bots skip Demon Hunter/Evoker (need an existing high-level character on the account). After GiveLevel *and* gear, dummy/test spells **and applied auras** with missing triggers are stripped (spell 155882 `RKS Dummy Effect Periodic Aura A` is often an item/aura, not a spellbook entry; log flood stalled the world thread and character create timed out as CHAR_CREATE_ERROR 25). GiveLevel is one bot per world tick. Character-create timeout uses `GameTimeMS`.
- `docker/etc/worldserver.conf.d/playerbots.conf` is a hand-maintained copy of `modules/mod-playerbots/conf/playerbots.conf.dist` (values differ: Random.Count 200, MinLevel 1 / MaxLevel 90): when a new `Playerbots.*` key is added to the `.dist`, add it to the docker copy too or the C++ default is used silently.
- mod-playerbots DB (2026-09-30): `modules/mod-playerbots/data/sql/db-characters/playerbots_00_schema.sql` creates AzerothCore's playerbots_* tables in the `characters` DB (a fifth pool is not needed), `_01_names` seeds `playerbots_names` (100000, `gender` column = name category race group*2+gender, NOT a gender), `_02_seed` the texts chance. Access only through `src/Db/PlayerbotRepository` (`sPlayerbotRepository`): read once in `WorldScript::OnStartup` (sync), async write-behind with `EscapeString`; used by `playerbots_db_store` (`strategies` for master bots via `PlayerbotAI::SaveState/RestoreState`, `home` for random bots), `playerbots_random_bots` (`randomize` event), `playerbots_account_type`, `playerbots_names` (`MakeName`), `playerbots_quest_blacklist`; the other tables are empty/unused (AC seed data is 3.3.5 specific). Test SQL in a scratch DB first (`docker exec -i trinity-mysql mysql ... pb_scratch < file`, then drop it).
- Bot placement/interruption (2026-09-30): `RandomBotMgr::Prepare` re-places every random bot once per `PlacementVersion` (event `placed` in playerbots_random_bots; bump the constant in `RandomBotMgr.cpp` to force a fresh reset at next login, `Place()` falls back to the race start position when `PickSpot` finds nothing). `PlayerbotAI::DetectInterruption` compares position/map each simulated tick (>60 yards or map/instance change, not during taxi) -> `OnInterrupted`: RPG `ChangeToIdle`, motion clear, `_interruptEpoch++` (QuestTravel drops its plan and skips log quests once), home moves to the new spot on open-world maps via `RandomBotMgr::UpdateHome`.
- mod-playerbots perf layer (2026-10-06): `Engine/PerfMonitor` (`PerfScope`, `.bot perf [reset]`, needs `Playerbots.PerfMon.Enable = 1`) times the relevance scan + each action; `Engine::DoNextAction` reuses a member candidate buffer; AI ticks are staggered per bot (random initial `_updateTimer`); `RememberStand`/`DetectInterruption` run once per UpdateInterval (after the gate); `IsSimulated` caches the humans-proximity verdict 500 ms; `SelectCombatTarget` is cached per AI tick (`GetTick()`), enemy and corpse grid searches wait `Playerbots.ScanInterval` (1500 ms) after an empty result. Build only the module with `cd build && make modules -j12` (~30 s), full link `make worldserver` (~30 s after that); new module .cpp files need `cmake .` first.
- mod-playerbots engine (2026-10-06, phase 2): `src/Engine/` = `Engine` (baskets by relevance, multipliers, prerequisites/alternatives, `ApplyStrategyString`, `ExecuteAction`), `AiContext` (per bot, lazily creates actions/triggers/values from `AiRegistry` by `name::qualifier`, `BeginTick` drives per-tick caches), `Trigger.h`/`Value.h`/`Multiplier.h` (free of core types). Generic strategies are now trigger -> action offers registered in `RegisterGenericAi()` (`GenericStrategies.cpp`, run once via `EnsureAiRegistered()`); `CreateStrategy(name)` is just the registry lookup. Legacy `AddAction`+`GetRelevance` strategies (rpg, quest) still work. Standalone engine test: `modules/mod-playerbots/tests/run_engine_test.sh` (g++ only, ~5 s). NOT yet play-tested in game.
- mod-playerbots chat commands (2026-10-06, phase 3): `src/Cmd/ChatParser` (@filters, `;` chains, longest-name command parse; core-type free, covered by `tests/chat_parser_test.cpp`) + `Cmd/ChatCommands.cpp` (command table, each command an action `cmd <name>` run through `Engine::ExecuteAction`; `HandleBotChat(ai, speaker, text, group)` is the single entry used by both `OnChat` hooks in `Script/PlayerbotsScripts.cpp`; `leave` is returned as `ChatOutcome.Leave` because the AI dies with the bot). `PlayerbotAI::HandleCommand` is gone. New keys `Playerbots.Command.Prefix/Separator/NearbyDistance`. `tests/run_engine_test.sh` runs both standalone tests. Not play-tested.
- mod-playerbots social (2026-10-07): `Social/BotSocialMgr` (named so its header does not shadow the core `SocialMgr.h`, whose `PlayerSocial` PlayerbotAI.cpp needs) answers `SMSG_PARTY_INVITE` / `SMSG_GUILD_INVITE` sent to random bots (packet on a map thread -> queued -> answered from `OnUpdate` via `HandlePartyInviteResponseOpcode` / `HandleGuildAcceptInvite`) and whispers to random bots not in the speaker's party. Before this, invites and whispers to random bots were never handled (only `.bot add` bots and LFG/BG fills). Keys `Playerbots.Random.GroupInvitations/GuildInvitations/WhisperReply`. A header in a module subdirectory that shares a name with a core header wins the include search: check names before adding files.
- mod-playerbots stage A (2026-10-07, city life): `Travel/PhaseGuard` (usable spawn phase = 0, 169 or a SHARED phase: in `phase_area` with no `conditions` row of type 26 anywhere, 128 phases; Midnight Silvermoon at map 0 around (8505,-4707) has 650 service NPCs in shared phase 24825, so a strict "default only" filter would leave it empty; ~335 quest ids from world `conditions` source types 25/26 incl. reference groups), `Travel/HubClusters` (pure) + rewritten `HubIndex` (clusters with tiers, all service bits per NPC, default-phase/difficulty filter, grid lookups), `Travel/Hotspots` (pure registry) + `HotspotMgr` (hubs -> hotspots, occupancy every 5 s, markers), `Script/npc_bot_hotspot.cpp` (marker AI, creature entries 9100001-9100205, SQL in `data/sql/db-world/2026_10_07_00_world_mod_playerbots_hotspots.sql` with table `playerbots_hotspot_marker`), `RandomBotMgr` (`PlacementVersion` 2, `PlaceAtHotspot`, anchors in db_store key `anchor`, `RotateBots` once a minute), rpg `CurrentAnchor()` in RpgStrategy.cpp. Social arrival points (auction house/bank/mail weighted) + anchor centre = arrival point; world table `playerbots_hotspot_override` (seed: Silvermoon level 80+). - mod-playerbots stage B (2026-10-07): `Travel/Graph/TravelGraph` (pure A*, `tests/travel_graph_test.cpp`), `Travel/TravelMgr` (`sTravelMgr`: graph from HubIndex clusters + taxi network (`sTaxiNodesStore`/`sTaxiPathStore`/`sTaxiPathNodesByPath`, 32 yd/s) + area trigger portals between non-instance maps + 6-nearest-neighbour walking links; `PlanFor(bot, goal)` adds the hearthstone as a temporary link; blocked links expire after 5 min; logs sample routes at startup), `Travel/RouteFollower` (per-bot state in `PlayerbotAI::GetRoute()`; legs walk/taxi/portal/hearth, 3 re-plans, virtual travel for frozen bots via the frozen branch of `PlayerbotAI::Update`, `NoteExpectedMove()` keeps its own teleports from counting as interruptions), `TakeTaxi` in `Travel/Taxi.cpp` (ActivateTaxiPathTo with no NPC), strategy `travel` (now a default strategy), chat `goto`, GM `.bot travel info|nodes|route`. Keys `Playerbots.Travel.Enable/MaxRouteMinutes/VirtualSpeedup/FreeFlights`. Walking links are straight-line estimates (not mmap-verified), boats/zeppelins = Transport links between the ground nodes next to the dock stops of each live `transports` row (taxi path STOP nodes, `moTransport.taxiPathID`; trip = TotalPathTime / stops + wait up to 150 s; gunships/raid ships excluded by name); nobody boards: real mode waits at the dock then teleports to the other dock, frozen bots jump ahead one stretch at a time after the stretch travel time clamped to `Playerbots.Travel.HopMinSeconds/HopMaxSeconds` (120/300), keys replaced VirtualSpeedup. Enemy ground + danger (ideas from AC TravelNode): `TravelNode.Team` (hub nodes of towns hostile to a team are closed to it, taxi nodes by map flags; the planner skips such nodes, `RouteFollower::Begin` refuses goals inside hostile towns via `IsHostileGround`), `Travel/DangerMap` (128 yd cells, highest creature level per team from the spawns, level = ContentTuning MinLevel + DeltaLevelMin, civilians/critters/triggers/unusable phases ignored), `TravelLink.DangerAlliance/Horde` set on walk links, cost +`Travel.DangerSecondsPerLevel` per level above bot+3, blocked at `Travel.DangerBlockLevels` (30/12); failed links block 5 min doubling per failure in a row (max a day) and are forgiven by `LinkWorked`. AC facts: its walk link generator needs a unit to path with and is called with none, so its graph comes from shipped 3.3.5 DB rows; its live walking (MoveFarTo) refuses enemy districts, walks navmesh vertices in capitals and counts 5 yd of progress. No quest/rpg use yet. Built, NOT deployed or play-tested.

- Playerbot design rule 2 (2026-10-07, user): two tiers. Near a human = player-like behavior; far (frozen/virtual) = strict, abstract, cheap, so hundreds/thousands of bots stay online without hiccups. World objects never gate bot abilities. Gathering was changed accordingly: `RpgStatus::Gather` is scenery only (bot with herbalism/mining walks to a node within `Rpg.GatherDistance` 120 yd, kneels/mines 3-5 s, node NOT used or looted, skill values irrelevant, `RpgInfo.Working` emote cleared on any status change); only simulated bots run rpg at all. Child skill lines in BotProfessions stay (harmless). Built, not deployed.

## Whisper fallback hook (2026-10-17)

`Social/WhisperFallback.h`: another module (mod-ollama) registers `Playerbots::SetWhisperFallback` while its scripts are
registered. A whisper to a bot that is not a playerbots command goes to it before "Unknown command" (master bots,
`HandleBotChat`) or the random bot hint (`BotSocialMgr::OnWhisper`, `PlayerbotsScripts.cpp`). Returning true means the
whisper is dealt with and playerbots stays quiet. Party chat needs no hook: playerbots only reads party lines that start
with `Playerbots.CommandPrefix`.
